## 2023-10-05 - Prevent CSP injection in OAuth consent page form-action
**Vulnerability:** A clickjacking vulnerability existed on the OAuth consent page because the `Content-Security-Policy` header dynamically incorporated the `redirect_uri` origin (`netloc`) without sufficient validation. An attacker could craft a malicious `redirect_uri` (e.g., `https://example.com'; frame-ancestors *`) containing CSP delimiters. While the URI validator checks for schemes and some control characters, it does not reject `;` or `'`. When `urllib.parse.urlparse` parsed this URI, the injected characters became part of the `netloc`, which was then embedded directly into the CSP `form-action` source string. This allowed the attacker to override the trailing `frame-ancestors 'none';` directive.
**Learning:** `urllib.parse.urlparse` is permissive and will include characters like semicolons and single quotes in the `netloc` component if they are part of a malformed or unusual authority segment. When reflecting URL components into structured security headers like CSP, relying solely on standard URL validation is insufficient because URL-safe characters can still be structurally significant in the context of the HTTP header.
**Prevention:** When dynamically constructing Content-Security-Policy (CSP) headers using components from parsed user-provided URLs, explicitly sanitize or reject strings containing CSP delimiters such as semicolons (`;`), single quotes (`'`), commas (`,`), or spaces.
